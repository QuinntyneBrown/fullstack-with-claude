Data and Security (non-negotiable)

- Zod-validate every input at every boundary: request bodies, query strings, route
  params, and Server Action form data.
- Parameterised SQL only, with `?` or named placeholders. Never build SQL by string
  concatenation or template interpolation, including `LIKE` search terms.
- All SQL lives in `lib/repositories/`. Nothing else touches `lib/db.ts` directly.
- Never store or log a plaintext password. Hash with scrypt (Node `crypto`) or
  bcrypt, with a per-user salt, and compare in constant time.
- No secrets in the repo: no keys, tokens, or credentials in source, tests, fixtures,
  or docs. Read configuration from environment variables.
- Authorise every note query by the signed-in user. A user must never read, edit,
  delete, or search another user's notes.
- Return generic errors for failed sign-in; do not reveal whether an email exists.

ATDDone criterion at a time

Do not skip ahead. Mocks come before frontend code.

Testing approach

  1. Write a Playwright test linked to a Given-When-Then criterion in docs/specs/
  2. Watch it fail for the right reason
  3. Implement until it passes, then refactor

Page objects own the selectors; tests state intent. Never write architecture tests.
